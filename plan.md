# План реализации уведомлений для матчей

## 1. Расширить типы уведомлений
- Создать enum или константы для типов уведомлений (`ROSTER_DECLARED`, `MATCH_STARTED`)
- Обновить интерфейс `MatchNotificationPayload` для указания типа уведомления

## 2. Модифицировать логику в `MatchWatcherService`
- Добавить проверку доступности заявки отдельно от стартового состава
- Создать метод для отправки уведомления о заявке (когда есть `event.teams.home/away.players`, но нет стартового состава)
- Сохранить существующую логику для уведомления о стартовом составе

## 3. Обновить кеширование в `MatchNotificationCacheService`
- Создать отдельные ключи кеша для каждого типа уведомления
- Обеспечить, чтобы каждый тип уведомления отправлялся только один раз

## 4. Расширить обработчик в `TelegramBotService`
- Добавить логику для форматирования уведомления о заявке
- Создать отдельные методы форматирования для каждого типа уведомления
- Обеспечить корректное отображение информации в зависимости от типа

## 5. Тестирование
- Проверить, что уведомление о заявке отправляется сразу при появлении информации
- Убедиться, что уведомление о стартовом составе работает как раньше
- Проверить, что дублированные уведомления не отправляются
