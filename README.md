# 🏐 Win-Factor - Volleyball Analytics Platform

Монолитное приложение на NestJS для парсинга и анализа волейбольных данных с VolleyStation.com, а также уведомлений пользователей через Telegram-бота.

## 📦 Архитектура

Проект представляет собой единое монолитное приложение, состоящее из модулей:

1. **VolleyStation Module** – парсинг данных с VolleyStation.com через HTTP и Socket.IO
2. **Monitoring Module** – бизнес-логика обработки турниров, команд, игроков и матчей
3. **Telegram Bot Module** – уведомления пользователей и статистика игроков

Вся логика реализована с использованием NestJS, DDD, CQRS и Event Sourcing для обеспечения масштабируемости и надежности.

```
┌──────────────────┐    Socket.IO     ┌─────────────────────────────────┐       ┌──────────────────┐
│                  │ ◄──────────────► │                                 │       │                  │
│ VolleyStation    │                  │        Win-Factor               │ ───▶  │ Telegram Bot     │
│ (External API)   │ ◄──────────────► │      (NestJS Monolith)          │       │ + Notifications  │
│                  │     HTTP         │                                 │       │                  │
└──────────────────┘                  └─────────────┬───────────────────┘       └──────────────────┘
                                                     │
                                                     ▼
                                            🛢 PostgreSQL + Redis
```

## 🧩 Модули

### 1. VolleyStation Module

- **Назначение:** Получение данных с VolleyStation.com через HTTP API и real-time мониторинг матчей
- **Технологии:**
  - NestJS + `@nestjs/axios`
  - Socket.IO клиент для real-time данных
  - Cheerio для парсинга HTML
  - Cloudflare Bypass Proxy (Python + mitmproxy)
- **Функции:**
  - Парсинг турниров, команд, игроков
  - Мониторинг live-матчей через Socket.IO
  - Получение статистики прошедших матчей

---

### 2. Monitoring Module (DDD Core)

- **Назначение:** Бизнес-логика обработки спортивных данных с использованием Domain-Driven Design
- **Архитектурные паттерны:**
  - Domain Entities: Competition, Team, Player, Match
  - CQRS для разделения команд и запросов
  - Event Sourcing для отслеживания изменений
  - Repository pattern для работы с данными
- **Технологии:**
  - NestJS + `@nestjs/cqrs` + `@nestjs/typeorm`
  - PostgreSQL для постоянного хранения
  - Redis для кэширования
  - BullMQ для очередей задач

---

### 3. Telegram Bot Module

- **Назначение:** Уведомления пользователей и предоставление статистики игроков
- **Функции:**
  - 🔔 Подписка на уведомления о конкретных игроках
  - 📊 Статистика игроков и их участие в матчах
  - 🚨 Уведомления о составах (кто отсутствует на скамейке/в заявке)
  - 📺 Трансляция в канал для массовых уведомлений
- **Технологии:**
  - `grammy` (современный Telegram Bot Framework)
  - Интеграция с Monitoring Module через CQRS
  - Redis для хранения пользовательских подписок

---

## ⚙️ Технические детали

### 🧱 Базы данных

- **PostgreSQL** для основного хранения (турниры, матчи, команды)
- **Redis** для кэширования, очередей и пользовательских сессий

### 🔄 Real-time Подключения

- **Socket.IO** для мониторинга live-матчей
- **WebSocket** для получения составов и статистики в реальном времени
- **Event-driven архитектура** для обработки событий

### 🔔 Telegram Уведомления

- **Личные уведомления** о любимых игроках
- **Канал для массовых уведомлений** о важных событиях
- **Статистика игроков** по запросу

### 🔐 Обход Блокировок

- **Cloudflare Bypass Proxy** на Python + mitmproxy
- **IP подмена** и модификация заголовков HTTP

## 🧪 Тестирование
